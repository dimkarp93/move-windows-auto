## 1. Сборка пакета

### Что получается

Из одного исходника собираются два пакета, потому что загрузчики расширений до GNOME 45 и после несовместимы:

| Архив | GNOME Shell | Формат |
|---|---|---|
| `dist/move-windows-auto@dimkarp93.legacy43.shell-extension.zip` | 43, 44 | legacy `imports.*` |
| `dist/move-windows-auto@dimkarp93.esm48.shell-extension.zip` | 45–48 | ES-модули |

В корне каждого архива лежат `metadata.json`, `extension.js`, `prefs.js`, `rules.default.json` и каталог `lib/`. Файл `metadata.json` обязан быть именно в корне архива, а не во вложенном каталоге.

### Перед сборкой

1. Выполните `just bump-version`. Рецепт поднимает `version` на единицу в обоих `src/*/metadata.json` (значение одно на оба файла) и подставляет в `url` адрес `origin` (SSH-адрес приводится к `https://...`, суффикс `.git` отбрасывается). Другой адрес задаётся аргументом: `just bump-version https://github.com/<владелец>/<репозиторий>`. Флаг `--keep-version` обновляет только `url` и git не трогает. Флаг `--no-git` правит файлы, но не делает коммит и тег. Без этих флагов рецепт после правки файлов коммитит оба `metadata.json` (сообщение `bump version to N`), создаёт аннотированный тег `vN` и публикует тег в `origin` (`git push origin refs/tags/vN`). Это запускает релиз в CI. Перед правками рецепт проверяет, что `origin` настроен, оба `metadata.json` уже под git и тег `vN` не существует ни локально, ни в `origin`; иначе он ничего не меняет. Ветка в `origin` рецептом не пушится: отправьте её сами (`git push origin <ветка>`). Рецепт отказывается работать, если `uuid` в файлах различается или оканчивается на `gnome.org`, а диапазоны `shell-version` пересекаются. Если у репозитория нет `origin` и адрес не передан, `url` остаётся прежним (`https://github.com/dimkarp93/move-windows-auto`), о чём выводится предупреждение.
2. Проверьте `uuid` (`move-windows-auto@dimkarp93`). После первой публикации его менять нельзя: для каталога это будет другое расширение. Часть после `@` должна быть вашим именем или доменом, не `gnome.org`.
3. Убедитесь, что `shell-version` покрывает только проверенные версии: пересечение диапазонов рецепт уже проверил.

### Сборка

```sh
just pack
```

Рецепт сначала запускает `lint` и `test`, затем `sh tools/build.sh --pack` и печатает содержимое каждого архива (`unzip -l`). Если нужны только архивы без проверок:

```sh
sh tools/build.sh --pack
```

### Проверка архива

```sh
unzip -l dist/move-windows-auto@dimkarp93.esm48.shell-extension.zip
unzip -p dist/move-windows-auto@dimkarp93.esm48.shell-extension.zip metadata.json
```

Чек-лист:

- `metadata.json` и `extension.js` в корне;
- нет `__pycache__`, `.git`, `node_modules`, бинарных файлов и минифицированного кода;
- `uuid` в `metadata.json` совпадает с тем, что вы собираетесь публиковать;
- версии `shell-version` соответствуют названию архива (`legacy43`: 43, 44; `esm48`: 45–48).

Затем поставьте архив локально, как описано в [части 2](#2-распространение-и-установка-из-файла), и проверьте, что расширение включается и окно настроек открывается.

### Сборка в CI

По тегу `v*` workflow `.github/workflows/ci.yml` прогоняет тесты и lint, собирает оба архива и прикладывает их к релизу GitHub. Этот тег создаёт и публикует `just bump-version`, отдельно ставить его не нужно.

## 2. Распространение и установка из файла

### Выложить

Самый простой способ: релиз на GitHub. Тег `v*` создаёт релиз с двумя архивами автоматически (см. выше). Либо отправьте `.zip` любым другим способом: оба файла самодостаточны.

Нужно сказать получателю, какой архив ему подходит:

| Дистрибутив | `gnome-shell --version` | Архив |
|---|---|---|
| Debian 12 | 43.x | `legacy43` |
| Debian 13 | 48.x | `esm48` |

### Скачать и установить

```sh
curl -LO https://github.com/dimkarp93/move-windows-auto/releases/latest/download/move-windows-auto@dimkarp93.esm48.shell-extension.zip
gnome-extensions install --force move-windows-auto@dimkarp93.esm48.shell-extension.zip
```

Файл ставится в `~/.local/share/gnome-shell/extensions/move-windows-auto@dimkarp93`. Флаг `--force` заменяет уже установленную версию.

### Включить

Shell не видит новое расширение, пока не перечитает список:

- **X11:** `Alt+F2`, `r`, Enter;
- **Wayland:** выйти из сессии и войти снова.

После этого:

```sh
gnome-extensions enable move-windows-auto@dimkarp93
gnome-extensions info move-windows-auto@dimkarp93
```

Штатное расширение `auto-move-windows` конфликтует по смыслу, его отключите вручную:

```sh
gnome-extensions disable auto-move-windows@gnome-shell-extensions.gcampax.github.com
```

Правила создаются при первом запуске в `~/.config/move-windows-auto/rules.json` из `rules.default.json`. Редактирование правил описано в [usage.md](usage.md).

### Обновить и удалить

Обновление: тот же `gnome-extensions install --force <новый.zip>`, затем перезапуск shell или перелогин. Файл правил при этом не затрагивается.

```sh
gnome-extensions uninstall move-windows-auto@dimkarp93
```

Файл `~/.config/move-windows-auto/rules.json` при удалении остаётся.

### Если не включается

```sh
gnome-extensions info move-windows-auto@dimkarp93
journalctl --user -b | grep -i move-windows-auto
```

Самые частые причины: архив не под свою версию GNOME Shell (в `info` будет состояние `OUT OF DATE`), не перезапущен shell, `metadata.json` лежит не в корне архива.

## 3. Публикация на extensions.gnome.org

Каталог проверяют люди, поэтому цикл «загрузил, получил отзыв, исправил» может занять от нескольких дней. Правила проверки: [Review Guidelines](https://gjs.guide/extensions/review-guidelines/review-guidelines.html). Перед отправкой перечитайте актуальную версию: требования меняются.

### Подготовка

1. Аккаунт на [extensions.gnome.org](https://extensions.gnome.org) (вход через GNOME-аккаунт).
2. Репозиторий с открытым исходным кодом и совместимой лицензией (GPL-2.0-or-later обычно подходит). В репозитории должен быть файл с лицензией, а в `metadata.json` реальный `url`.
3. Решите вопрос с `uuid` заранее (см. часть 1).
4. Подготовьте описание и 1–3 скриншота окна настроек для страницы расширения.

### Что проверяют рецензенты

Расширение уже написано с учётом большинства требований, но стоит пройтись по пунктам:

- **Всё созданное в `enable()` убирается в `disable()`**: сигналы, таймеры (`GLib.timeout_add`), D-Bus-объекты и владение именем. В `Controller.disable` это делается.
- **Нет подмены приватного API.** Расширение не патчит методы shell и не создаёт workspace: оно рассчитано на фиксированное число рабочих столов.
- **Нет лишнего кода**: минифицированных и сгенерированных файлов, неиспользуемых модулей, бинарей, вызовов внешних программ через `GLib.spawn*`. Из исходников собирается только то, что нужно.
- **Нет телеметрии и обращений в сеть.** В расширении их нет.
- **Файлы вне каталога расширения.** Расширение читает и пишет `~/.config/move-windows-auto/rules.json`. Это нужно указать в описании.
- **Исходники читаемы**, архив собран из них без шагов, которых нет в репозитории (`tools/build.sh` лежит рядом).

Если в загрузке есть сгенерированный `legacy`-код, приложите в описании ссылку на репозиторий и команду сборки (`sh tools/build.sh`), чтобы рецензент мог воспроизвести архив.

### Загрузка

1. Откройте [Upload](https://extensions.gnome.org/upload/) и выберите архив. Начните с `esm48`.
2. Если сервер отклонит файл, текст ошибки скажет, чего не хватает в `metadata.json` или архиве.
3. Заполните описание, добавьте скриншоты, отметьте ссылку на репозиторий.
4. Отправьте на проверку. Расширение станет видно после одобрения.

Для legacy-версии повторите загрузку с архивом `legacy43`: один и тот же `uuid`, другой набор `shell-version`. Каталог отдаёт пользователю версию, подходящую его shell. Поле `version` каталог при загрузке переназначает по своей нумерации, но для порядка поднимайте его в каждом выпуске.

### Статус проверки и исправления

Статус проверки (одобрено, нужны правки или отклонено) виден на странице расширения в вашем аккаунте. После правок поднимите `version`, соберите архив заново (`just pack`) и загрузите снова: на ту же страницу, а не как новое расширение.

### Установка из каталога

Пользователю достаточно открыть страницу расширения и переключить тумблер. Для этого нужен браузерный коннектор:

```sh
sudo apt install gnome-shell-extension-manager
```

Либо расширение «Extension Manager», либо `gnome-browser-connector` и расширение для браузера со страницы каталога. Можно и без браузера:

1. скачать архив со страницы расширения (кнопка загрузки);
2. поставить его: `gnome-extensions install --force <архив>`.

Обновления приходят автоматически: GNOME Shell сверяется с каталогом по `uuid` и предлагает новую версию через Extension Manager или браузерный коннектор.

### Выпуск новой версии, коротко

1. `just bump-version`: версия, `url`, коммит и тег `vN` в `origin`.
2. `just pack`, проверить архивы.
3. Запушить ветку (`git push origin <ветка>`): коммит и тег `vN` уже созданы рецептом, тег опубликован, релиз на GitHub соберётся сам.
4. Загрузить оба архива на extensions.gnome.org.
5. Дождаться проверки.
