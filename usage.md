# move-windows-auto: руководство пользователя

Расширение GNOME Shell, которое раскладывает окна по рабочим столам (workspace) по правилам. В отличие от штатного `auto-move-windows`, правило может опираться не только на приложение, но и на **заголовок окна**, класс, роль, размер и положение. Так обычное и приватное окно браузера, или окна редактора с разными проектами, попадают на разные workspace.

Инструкция для разработчиков: [README.md](README.md).

## Требования

| Дистрибутив | GNOME Shell | Проверено |
|---|---|---|
| Debian 12 «bookworm» | 43 | да |
| Debian 13 «trixie» | 48 | да |

Версии 44 и 45–47 заявлены в метаданных, но отдельно не проверялись. GNOME 49 и новее не поддерживается. Версию shell показывает `gnome-shell --version`.

Работает и в X11, и в Wayland-сессии. В Wayland нет некоторых свойств окон, см. [ограничения](#ограничения).

Для установки из репозитория нужны:

- `git` — склонировать репозиторий;
- `gjs` — `just dev` перед установкой прогоняет тесты, на нём же работают `just inspect`, `just add-rule`, `just debug` и `just doctor`;
- `just` версии 1.27 или новее. В Debian 13 это пакет `just`, в Debian 12 пакета нет, `just` ставится с [github.com/casey/just](https://github.com/casey/just).

```sh
sudo apt install git gjs
sudo apt install just    # только Debian 13
```

## Установка из репозитория

```sh
git clone https://github.com/dimkarp93/move-windows-auto.git
cd move-windows-auto
just dev
```

`just dev` делает всё сразу:

1. запускает проверки;
2. собирает версию, подходящую вашему GNOME Shell (43 или 48, определяется автоматически);
3. ставит расширение в `~/.local/share/gnome-shell/extensions/move-windows-auto@dimkarp93` (это симлинк на каталог `build/` репозитория, поэтому репозиторий после установки удалять нельзя);
4. создаёт файл правил `~/.config/move-windows-auto/rules.json`, если его не было;
5. **отключает штатное расширение `auto-move-windows`**, чтобы они не конфликтовали, и включает это;
6. перезапускает GNOME Shell.

Перезапуск shell работает не везде:

- **X11:** `just dev` попробует перезапустить shell сам. Если не получилось (без unsafe-mode это обычно так), нажмите `Alt+F2`, введите `r`, `Enter`.
- **Wayland:** перезапустить shell нельзя. Выйдите из сессии и войдите снова.

### Установка из готового архива

Если не хотите собирать сами, возьмите архив нужной версии:

```sh
# Debian 12 (GNOME Shell 43)
gnome-extensions install --force move-windows-auto@dimkarp93.legacy43.shell-extension.zip
# Debian 13 (GNOME Shell 48)
gnome-extensions install --force move-windows-auto@dimkarp93.esm48.shell-extension.zip
```

Затем перелогиньтесь (Wayland) или перезапустите shell (X11) и выполните:

```sh
gnome-extensions disable auto-move-windows@gnome-shell-extensions.gcampax.github.com
gnome-extensions enable move-windows-auto@dimkarp93
```

Файл правил в этом случае создаётся при первом запуске расширения из набора по умолчанию.

## Первый запуск

Проверьте, что расширение загрузилось:

```sh
just status
```

В выводе должна быть строка о том, что расширение включено (`ENABLED`). Затем откройте окно настроек:

```sh
just prefs
```

Окно открывается и кнопкой настроек у расширения в приложении «Расширения» (Extensions).

Набор правил по умолчанию (`rules.default.json`) написан под конкретную рабочую среду: Firefox ESR, VS Code, Evince, kitty, Telegram, VPN-клиенты, Obsidian, LM Studio. Замените его своим: проще всего через [страницу «Снимок»](#страница-снимок).

## Возможности

- **Правила по свойствам окна.** Заголовок, класс (`WM_CLASS`), роль, идентификатор приложения, тип окна, командная строка процесса, размер, положение, монитор, «развёрнуто на весь экран».
- **Порядок имеет значение.** Применяется первое совпавшее правило, поэтому специфичные правила ставьте выше общих.
- **Умное ожидание заголовка.** Заголовок окна часто появляется не сразу. Расширение переносит окно по лучшему из уже совпавших правил, а если потом заголовок подойдёт под более точное правило, переносит ещё раз (максимум через `settleMs`, по умолчанию 2,5 с). Окно, для которого нет подходящих правил, остаётся там, где открылось.
- **Дополнительные действия правила.** Перейти на нужный workspace (`follow`), сфокусировать окно (`focus`), перенести на другой монитор (`monitor`).
- **Отрицание.** У каждого текстового предиката есть форма с суффиксом `Not`: `titleNot`, `wmClassNot` и так далее.
- **Окно настроек.** Редактор правил со страницей «Правила» и страницей «Снимок», импорт и экспорт, проверка перед сохранением.
- **Применение по «Сохранить».** Кнопка «Сохранить» в окне настроек записывает `rules.json` и сразу применяет его в расширении без перезапуска shell. Правки в интерфейсе до сохранения на расширение не влияют, как и правка файла вручную: для неё вызовите D-Bus-метод `Reload`. Если файл сломан, продолжают действовать прежние правила.

## Настройка

Правила хранятся в `~/.config/move-windows-auto/rules.json`. Редактировать можно в окне настроек или прямо в файле.

### Окно настроек

#### Страница «Правила»

- Каждое правило — раскрывающаяся строка: название, workspace, переключатели «перейти» и «сфокусировать», монитор и список предикатов.
- Кнопки в строке: **выше**, **ниже**, **дублировать**, **удалить**. Порядок правил значим.
- Текстовые предикаты вводятся как регулярные выражения; рядом поле флагов (например, `i` — без учёта регистра). Числовые принимают `800` или диапазон `800..1200` (также `..1200` и `800..`). Предикат `maximized` — переключатель.
- Чтобы добавить предикат, выберите его в списке и нажмите «+».
- Изменения живут в памяти до нажатия **«Сохранить»**. Перед записью набор проверяется так же, как это делает расширение, поэтому в файл не попадёт то, что оно отвергнет.
- Меню рядом с «Сохранить»: **Импорт…**, **Экспорт…**, **Отменить изменения**.
- Общие настройки: задержка распознавания (`settleMs`, от 2000 мс) и отладочный журнал.

#### Страница «Снимок»

Самый быстрый способ создать правила:

1. Разложите окна по нужным workspace вручную.
2. Откройте `just prefs`, страницу «Снимок», нажмите **«Зафиксировать»**.
3. Расширение покажет список открытых окон и предложит правило на каждое.
4. Снимите флажок слева у окон, которые двигать не нужно. Флажки внутри строки включают и выключают отдельные предикаты, все выражения можно править.
5. Нажмите **«Добавить правила»**. Правила допишутся к текущему набору и сразу сохранятся: правило с точно таким же условием заменится на месте, правило с заголовком встанет выше общего правила того же приложения.

Заголовок в предложенное правило попадает **только если окна одного приложения лежат на разных workspace**. Берётся кратчайший отличающийся хвост заголовка, например ` - containers - Visual Studio Code$`.

Страница работает через запущенное расширение: оно должно быть включено, а после обновления кода shell перезапущен.

### Файл `rules.json`

```json
{
  "settleMs": 2500,
  "debug": false,
  "rules": [
    {
      "name": "firefox-private",
      "match": {
        "wmClass": "^firefox-esr$",
        "title": "Приватный просмотр|Private Browsing"
      },
      "workspace": 8
    },
    {
      "name": "firefox",
      "match": { "appId": "^firefox-esr\\.desktop$" },
      "workspace": 2,
      "follow": true
    }
  ]
}
```

Верхний уровень:

| Поле | По умолчанию | Назначение |
|---|---|---|
| `rules` | обязательно | массив правил |
| `settleMs` | `2500` | сколько ждать финального заголовка окна, мс; не меньше `2000` |
| `debug` | `false` | подробный журнал |

Правило:

| Поле | По умолчанию | Назначение |
|---|---|---|
| `name` | `rule #N` | название; в сообщениях об ошибках и в журнале |
| `match` | обязательно | условия, объединяются по И; хотя бы одно |
| `workspace` | обязательно | номер workspace, с 1 |
| `follow` | `false` | переключиться на этот workspace |
| `focus` | `false` | сфокусировать окно |
| `monitor` | не переносить | номер монитора, с 0 |

**Применяется первое совпавшее правило.** Поставьте специфичные правила выше общих.

### Предикаты (`match`)

| Предикат | Тип | Примечание |
|---|---|---|
| `appId` | regex | идентификатор `.desktop`-файла, например `^firefox-esr\.desktop$` |
| `wmClass` | regex | **второе** поле `WM_CLASS` |
| `wmClassInstance` | regex | **первое** поле `WM_CLASS` |
| `role` | regex | `WM_WINDOW_ROLE`, различает окна одного приложения |
| `gtkAppId` | regex | только у GTK-приложений |
| `windowType` | regex | `normal`, `dialog` и так далее; без этого предиката рассматриваются только обычные окна |
| `cmdline` | regex | командная строка процесса; не годится для приложений, которые держат один процесс на все окна |
| `title` | regex | заголовок окна; основной инструмент |
| `width`, `height`, `x`, `y`, `monitor` | число или `{"min": 1, "max": 2}` | геометрия рамки окна |
| `maximized` | `true` или `false` | развёрнуто по обеим осям |

- Regex можно задать с флагами: `{ "pattern": "\\.pdf$", "flags": "i" }`.
- Отрицание: `titleNot`, `appIdNot` и так далее, только для текстовых предикатов.
- В JSON обратную косую надо удваивать: `\\.` вместо `\.`.

### Как узнать значения для правила

Два способа, оба из каталога репозитория:

```sh
just inspect -d 3
```

Даёт 3 секунды переключиться на нужное окно, затем печатает его поля и готовый блок `match`. Остаётся придумать `name`, выбрать `workspace` и вставить в `rules.json`.

```sh
just add-rule vscode-containers 4 -d 3
```

Делает то же и сразу вставляет правило в `~/.config/move-windows-auto/rules.json`: имя и workspace задаются аргументами, `title` отбрасывается (он меняется, ключ `-t` его оставляет). Правило с тем же `match` заменяется на месте и сохраняет прежнее имя, более конкретное встаёт выше общего правила того же окна. Имя, занятое правилом с другим `match`, не принимается. Файл записывается в том же формате, что и окно настроек. Перед записью результат проверяется так же, как это делает расширение, при ошибке файл не меняется. Если правится рабочий конфиг, расширению отправляется `Reload`. Чтобы править файл из репозитория: `-f rules.default.json`.

```sh
just windows
```

Печатает **все** открытые окна в сыром виде (JSON внутри строки). Удобно, чтобы проверить, что расширение отвечает, и сравнить, какие значения оно видит у разных окон.

Если проще, воспользуйтесь [страницей «Снимок»](#страница-снимок).

### Примеры

**Приватные окна браузера отдельно:**

```json
{ "name": "firefox-private",
  "match": { "wmClass": "^firefox-esr$", "title": "Приватный просмотр|Private Browsing" },
  "workspace": 8 },
{ "name": "firefox", "match": { "appId": "^firefox-esr\\.desktop$" }, "workspace": 2 }
```

**Проект редактора на своём workspace:**

```json
{ "name": "code-containers",
  "match": { "wmClass": "^code$", "title": " - containers - Visual Studio Code$" },
  "workspace": 4 },
{ "name": "code", "match": { "appId": "^code\\.desktop$" }, "workspace": 1 }
```

**Документ с определённым именем, без учёта регистра:**

```json
{ "name": "pdf-pinned",
  "match": { "wmClass": "^Evince$", "title": { "pattern": "^manual\\.pdf", "flags": "i" } },
  "workspace": 9 }
```

**Всё на втором мониторе и с переключением:**

```json
{ "name": "chat", "match": { "appId": "^org\\.telegram\\.desktop" },
  "workspace": 5, "monitor": 1, "follow": true }
```

**Все окна приложения, кроме диалогов:**

```json
{ "name": "gimp", "match": { "wmClass": "^Gimp$", "titleNot": "Preferences" }, "workspace": 6 }
```

## Горячие клавиши

**Горячих клавиш у расширения нет.** Оно работает автоматически при открытии окон и ничего не перехватывает с клавиатуры.

Единственное сочетание, связанное с ним, штатное для GNOME: `Alt+F2`, затем `r` и `Enter` перезапускает GNOME Shell (только X11).

Если нужна быстрая команда, настройте сочетание в системных настройках (Параметры, Клавиатура, Комбинации клавиш), привязав его, например, к `gnome-extensions prefs move-windows-auto@dimkarp93`.

## Если что-то не работает

### Правило не срабатывает

1. Включите отладку и смотрите журнал:
   ```sh
   just debug on
   just logs
   ```
2. Откройте окно. В журнале строка `window created {...}` показывает значения, которые видит расширение. Сравните их с `match`.
3. Частые причины: перепутаны `wmClass` и `wmClassInstance`; не экранированы точки и скобки в регулярном выражении; в JSON одна косая вместо двух.
4. Когда разберётесь: `just debug off`.

Пример журнала:

```
MWA: window created {"appId":"example-app.desktop","wmClass":"example-app",...}
MWA: [app] -> workspace 1 (created, provisional)
MWA: waiting up to 2500ms for [app-special-window] on: title
MWA: [app-special-window] -> workspace 4 (notify::title)
```

Метка `provisional` означает предварительный перенос, который может уточниться. Метка `confirmed` — время ожидания вышло, и перенос стал окончательным.

### Окно переносится дважды

Так и задумано: сначала по общему правилу, потом, когда пришёл заголовок, по специфичному. Избежать можно, только если специфичное правило опирается на стабильные признаки (`wmClass`, `role`), а не на заголовок.

### Все окна переносятся с задержкой

В одном из правил заданы только изменчивые условия (например, только размер). Добавьте в него `wmClass` или `appId`.

### Расширение не загрузилось

```sh
just status
just doctor
```

`just doctor` собирает версию shell, тип сессии, состояние расширения, конфиг и таблицу окон. Приложите его вывод к сообщению об ошибке.

### Некорректный `rules.json`

В журнал пишется ошибка с названием проблемного правила, а прежние правила продолжают работать. Исправьте файл или откройте `just prefs`: окно покажет причину.

### Ограничения

- Заголовки окон локализованы: правило по тексту заголовка должно перечислять все языковые варианты через `|`.
- Совпадение по заголовку нестрогое: окно, случайно содержащее нужный текст в заголовке, тоже подойдёт.
- Расширение рассчитано на фиксированное число рабочих столов («Настройки» → «Многозадачность» или `gsettings set org.gnome.mutter dynamic-workspaces false`). Рабочие столы оно не создаёт: правило с номером больше их числа не применяется, в журнал пишется предупреждение. При динамических рабочих столах срабатывают только правила на уже существующие.
- Workspace нумеруются с 1.
- **Wayland:** нативные окна не имеют `WM_WINDOW_ROLE`, поэтому `role` у них пуст, а `wmClassInstance` может совпадать с `wmClass` или отсутствовать. Для таких окон опирайтесь на `appId` и `wmClass`.
- Перезапустить GNOME Shell из командной строки можно только на X11.

## Удаление

```sh
just uninstall
```

Отключает и удаляет расширение: снимает симлинк после `just dev` или удаляет установку из архива. Код остаётся загруженным в shell до его перезапуска (X11: `Alt+F2`, `r`; Wayland: перелогин). Файл `~/.config/move-windows-auto/rules.json` не трогается. Штатное `auto-move-windows` при желании включите обратно:

```sh
gnome-extensions enable auto-move-windows@gnome-shell-extensions.gcampax.github.com
```
