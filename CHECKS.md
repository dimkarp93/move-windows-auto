# Проверки

`just test` — логика без gnome-shell, `just live` — поведение окон в живой сессии, `just doctor` — снимок окружения, `just lint` — статический поиск необъявленных имён. Перечни конкретных утверждений находятся в `tests/`.

## Состав

Проверка, выполнимая без gnome-shell, принадлежит `just test`; в `just live` входит только то, что подтверждает связь с реальным Mutter. Одному исходу `Matcher.evaluate` соответствует одно live-окно — этим задан состав сценариев.

### just test

| Проверка | Назначение |
|---|---|
| матчер на фикстурах | фикстуры сняты с реальных окон через `xprop`; ключевое — логика ожидания: обычный Firefox ждёт правила приватного окна, терминал переносится сразу |
| валидация конфига | каждая ошибка называет проблемное правило по имени, иначе конфиг не поддаётся исправлению |
| прогон против `rules.default.json` | заодно подтверждает осмысленность конфига по умолчанию |
| `syntax.js` | файлы сборок исполнить вне shell нельзя, поэтому проверяется разбор: legacy через `new Function`, ES-модули через `import()` (ошибкой считается только `SyntaxError`, недоступные `resource://` ожидаемы); сборки не смешивают системы модулей; `metadata.json` объявляет непересекающиеся диапазоны `shell-version`, включая 43 и 48 |
| обе сборки | `tests/run.js` прогоняет матчер, валидацию, логику окна настроек и D-Bus-контракт и по `src/lib` (ESM), и по `build/legacy43`: автоматическое переписывание не может молча изменить поведение. `tests/cli.js` проверяет логику `tools/mwa.js`: заготовку правила, добавление в `rules.json`, таблицу окон |
| логика окна настроек | `prefs_model.js` не зависит от Gtk: разбор диапазонов и regex с флагами, перестановка и дублирование правил, выбор предикатов в снимке, слияние с валидацией, запись и чтение `rules.json` |
| `just lint` | ESLint `no-undef` и `no-unused-vars` по `src/`: единственная проверка кода, который исполняется только внутри shell |

### just live

Окна поднимаются через `kitty --class` с заголовком, меняемым escape-последовательностью: имитация VSCode без обращения к посторонним окнам. Конфиг подменяется на тестовый и восстанавливается через `trap`, включая `Ctrl+C`.

| Сценарий | Исход `evaluate` | Назначение |
|---|---|---|
| группа проверок конфига | — | правка файла сама не применяется; явный `Reload` применяет конфиг; некорректный JSON не выводит расширение из строя; исправленный конфиг подхватывается снова |
| `mwa-check-plain` | `apply` | окно без волатильной неопределённости переносится при создании, без предварительного шага |
| `mwa-check-refine` | `wait` → сигнал | отложенный матчинг доводит окно до специфичного правила, до уточнения окно припарковано |
| `mwa-check-ignored` | `none` | окно без подходящих правил остаётся на месте, решение принимается сразу |
| `mwa-check-stale` | `wait` → дедлайн | таймер срабатывает; `_onDeadline` вызывает `Matcher.resolve`; повторного переноса нет, только `Placer.activate` с `follow` и `focus` |

## Неочевидные проблемы

- Без `--since "@<epoch>"` в вывод journal попадают строки предыдущих прогонов.
- Уточнение утверждается как «до дедлайна»: сигнал приходит и от `tracked-windows-changed`.
- Активный workspace плавает, поэтому позиция окна замеряется дважды, а не сравнивается с сессией.
- Сценарий `stale` ловит отказ таймера: одного отрицания дедлайна недостаточно.
- `wmctrl -lx` при `BadWindow` завершает процесс — перечисления идут через `list_windows`.
- `wmctrl -c` матчит по заголовку и однажды закрыл постороннее приватное окно.
- `WM_CLASS` хранит пару `(instance, class)`: `wmClass` — второе поле, не первое.
- `dbus-send` возвращает код 0 даже при заблокированном `org.gnome.Shell.Eval`.
- Zip собирает `tools/build.sh`, а не `gnome-extensions pack`: тот без `--extra-source` теряет `lib/` и `rules.default.json`.
- Паузы в `live.sh` привязаны к `settleMs` и требуют пересмотра при его правке.

## Не покрыто автоматически

Весь код, требующий `Meta`/`Shell` (`lib/mover.js`, `lib/placer.js`, точки входа): ветвь `not applied:` в `place()`, снятие сигналов в `disable()`, загрузка под GNOME 48 и Wayland; окно настроек целиком (виджеты Gtk/Adw). Требуют перезагрузки `gnome-shell` или правки `gsettings` живой сессии. Проверка на реальных приложениях выполняется разово вручную при `just debug on`.
